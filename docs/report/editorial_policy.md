# 知的財産権リスク啓蒙サイト (digital-literacy-ip) 仕様書および記事作成基本方針

## 1. プロジェクト概要
一般社会人や学生を対象に、実際の事例をベースとした著作権法違反のリスクを啓蒙するためのウェブサイトです。強烈なインパクトを与えるデザインと、専門性の高い解説を両立した「啓蒙プラットフォーム」として構築されています。

- **プロジェクト名**: digital-literacy-ip
- **コンセプト**: 実例ベースのリスク啓蒙
- **公開URL**: https://digital-literacy-ip.vercel.app/
- **最終更新**: 2026年4月23日

---

## 2. デザイン・UI/UX仕様

### 2-1. デザインコンセプト：警戒モード (Caution Mode)
「Premium High-Contrast Warning Theme」を採用し、法的リスクの重大さを視覚的に伝えます。

- **配色**: 
  - メイン背景：プレミアム・ダークテーマ（黒基調）
  - 本文・サブタイトル：白（#fff）で視認性を最大化
  - 外部リンク：オレンジ（#ff9900）
  - アクセント：イエロー×ブラックの警戒ストライプ（Caution Tape）
- **エフェクト**: パネル外周へのグロー（発光）効果、背景の微細なテクスチャ。
- **フォント**: Noto Sans JP, Outfit。

### 2-2. 画面構成
- **ホーム画面**: 
  - シングルスクリーンのグリッドUI。
  - 「トレント」「ファスト動画」「海賊版」の3つの主要カテゴリを巨大なパネルで選択。
- **記事一覧・詳細**:
  - 「FILE XX」形式の証拠資料を模したカードデザイン。
  - 余計な見出し（「締めの言葉」等）を排除したクリーンな本文構成。
- **Wikiセクション**:
  - 法的知識を体系化するための別セクション。

## 3. 技術・システム構造

### 3-1. 開発スタック
- **テンプレートエンジン**: Nunjucks (custom `build.js` による静的生成)
- **開発ツール/ビルド**: Vite (HMR環境の提供、Environment Injection による環境変数管理)
- **パッケージ管理**: Node.js / npm

### 3-2. フロントエンド機能
- **ナビゲーション**: SPA（Single Page Application）構成。
  - **History API**: ブラウザの「戻る」「進む」操作に完全対応。
  - **URLハッシュ連携**: ハッシュによる直接アクセス管理。
- **記事間遷移**: 記事末尾の「次の記事へ」ボタンの自動パス解決機能。

### 3-3. バックエンド・インフラ仕様
- **アーキテクチャ**: SSG (Static Site Generation)
  - サーバーサイドの動的処理を排し、ビルド時に全てのHTMLを生成することで、極めて高い応答性能とセキュリティを確保。
- **データ管理（ファイルベースDB）**:
  - 従来のRDBMS（SQL等）は使用せず、`src/` 配下の構造化された Markdown およびテキストファイルをデータソースとして利用。
  - 専門データベース（法律・ツール・事件）のデータはフォルダ構造に基づき体系化。
- **インフラ・デプロイ**:
  - **ホスティング**: Vercel
  - **CI/CD**: Git（GitHub/Vercel連携）による自動デプロイ。
  - **環境管理**: 開発・本番環境の差異はビルド時の環境変数注入により吸収。

## 6. 記事作成・編集の基本方針

新規に記事を追加・編集する際は、ユーザーの理解を助け、ブランドイメージを一定に保つために、以下の基本方針に厳密に準拠してください。

### 6-1. HTML構造と枠組み (FILE 01-01 準拠)
各記事は最大2つのメインセクション構造（`glass article-card`）で構成し、視覚的な一貫性を確保します。

1. **第1セクション（事件概要と挿絵）**:
   - セクションタグ: `<section class="glass article-card" style="margin-bottom: 3rem;">`
   - セクションの先頭（見出しの前）に、以下の挿絵用画像ブロックを必ず挿入します。
     ```html
     <div style="text-align: center; margin-bottom: 3rem; margin-top: 2rem;">
         <img src="/img/img_article-[カテゴリID]/[画像ファイル名].png" alt="挿絵画像" style="max-width: 80%; height: auto; border-radius: 12px; box-shadow: 0 8px 32px rgba(0,0,0,0.5); border: 1px solid rgba(255,255,255,0.1);">
     </div>
     ```
   - 事件概要などのリード文を流れるような文章で記述します。
2. **第2セクション（法規と摘発の現実）**:
   - セクションタグ: `<section class="glass article-card">`
   - 具体的な適用法条、統計や警告表示（危険パネルなど）を配置します。
   - 記事全体の「まとめ」や「結びの段落」もこの第2セクションの中に内包し、外出しのセクションを作成しないようにします。

### 6-2. 文章トーンと口調の統一 (ですます調)
- 本文全体は自然な**ですます調（敬体）**で統一します（「である調」や箇条書きの言い切り表現「〜した」「〜である」などは避けます）。
- 事件の経緯やタイムラインを説明する際も、箇条書きによる事実の羅列を避け、ですます調の読みやすい文章段落（`<p>`）として再構成します。

### 6-3. 不要なメタ情報の排除
- 「基本ステータス（FILE ID、カテゴリ、重要度、タグなど）」のような、読者にとってノイズとなる機械的なステータス表記ブロックや、それに伴う不要な区切り線（`<hr>`）は一切掲載しないようにします。

### 6-4. 外部リンクのスタイル
- 記事内で公的機関（警察庁やCODA等）や判例等の信頼できる外部リソースへリンクする際は、リンクテキストの色をオレンジ（`#ff9900`）に統一し、外部リソースであることを分かりやすく提示します。

### 6-5. 挿絵プロンプトの作成方針（ChatGPT向け）
新規記事の挿絵を生成する際、ChatGPT（DALL-E）に入力する画像生成プロンプトは、以下の基準に従って設計・記述してください。

1. **記述言語**:
   - プロンプトは**日本語**で記述します。
2. **画像サイズ（アスペクト比）の指定**:
   - アスペクト比は **16:9（横長）** を指定します。（例：「アスペクト比16:9の横長画像」とプロンプトの冒頭に明記します）
3. **画風・スタイル指定**:
   - **写実性**: フォトリアリスティック（実写のような質感）を指定します。
   - **色調コントロール**: 全体的に冷たいモノクロや低彩度を基調とします。PCモニターの青白い光や、警告を意味する不気味な赤い光の糸、警戒イエロー、ネオンゴールドなど、極めて限定的な差し色（ネオン/発光効果）のみを使用するように指定します。
   - **トーン**: シリアスで緊迫感と絶望感のある「社会派エディトリアルデザイン風（新聞の社会面・特集記事の挿絵）」を指定します。
4. **構図・画面構成の指定（3層構造）**:
   - 1枚のシームレスな画像の中で、以下の3つのレイヤー（前景・中景・後景）の要素を組み合わせて描画するよう指示します。
     * **前景（手前）**: 目先の「小さな誘惑」や「気軽な行動」を象徴するクローズアップ（例：キーボードの上の手、スマートフォンのタップ画面、机の上の書類など）。
     * **中景（中間）**: 無自覚にリスクが拡散している様子（例：モニターから部屋全体やネット世界へ広がる無数の不気味な赤い光の糸、データ通信ラインなど）。
     * **後景（奥）**: ほんの出来心が招いた「突然の破滅・逮捕」を暗示するシルエット（例：朝の光が差し込む玄関のすりガラス越しに浮かぶ、手錠を持った警察官や捜査員たちの威圧的な黒いシルエット）。
5. **実在の人物・ロゴ・著作権物の排除**:
   - 実在の個人、企業ロゴ、登録商標、および既存の著作権キャラクター（ミッキーマウスなど）は一切含めないようにします。代わりに「シルエットの人物」「匿名のPCユーザー」などの表現を使用します。
